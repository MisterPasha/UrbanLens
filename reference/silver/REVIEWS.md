Requires migrations through 0009 and current steps 20–22 data. On a secondary
database, add `--registry data/silver/resolution-run-local.json` to import the
same canonical/replacement IDs from a verified run. Input records must match.

- Keep using `--apply-reviews` after import. The plain step 23 command protects
  existing IDs by refusing implicit merges/splits.
- Reviews bind provider, scope, source key, generation and semantic hash. Stale
  or conflicting mappings fail transactionally. A changed definition needs a new
  version; immutable prior definitions and outputs remain in S3.
  Processing logic also carries an explicit review-engine version.
- Accepted merges retain a deterministic existing UUID. Splits retain it for
  the largest current member group; other groups receive new UUIDs. Prior links
  and canonical records remain available for audit. Current records have active
  source links or a reviewed replacement entry.
- Explicit current-name overrides come first; otherwise prefer a named, current
  OSM record, then FSA. Addresses/points are not automatically switched to OSM.
  Inactive labels cannot supply selected fields or count as current hospitality.
- Retail/institution exclusions are source-specific. An excluded retailer record
  does not automatically exclude a separately evidenced café/pub in the same group.
- Every selected field records its value, observation/evidence source and review
  definition. Changes close the earlier validity period; exact replays add none.
- Date-only confirmations remain dates. Original source acquisition/observation
  dates stay intact. No opening/closure events are generated by corrections.
